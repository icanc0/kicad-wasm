## What's next (unblocks common tree)

The bottleneck now is stubbing more wx UI-adjacent headers that
KiCad's "common" (non-UI) code includes transitively:

- `widgets/kistatusbar.h` — needs wx/statusbr.h stub
- `wx_filename.h` — KiCad wrapper needing wxFileName
- `wx/dc.h`, `wx/font.h`, `wx/settings.h`, `wx/renderer.h` — the
  render-adjacent classes even non-render code touches
- `wx/wxcrt.h`, `wx/utils.h`, `wx/msgout.h`

Then linker-side: many kicommon files need functions defined
elsewhere in kicommon (or in wxWidgets itself). Each will need
either a stub function or the actual source file compiled.

## Realistic time estimate

Reaching a **compiling** `libkicommon.a` is estimated **20-40 more
turns** of stub iteration (compile file → grep unknown symbol →
add stub → repeat). That's most of the ROADMAP.md Phase 1 work.

Reaching **plotSVG in the browser** (M1.4) requires kicommon PLUS
a subset of pcbnew's plot path PLUS SVG_PLOTTER PLUS the board
model. Another **50-100 turns** on top.

M2 (browser PCB viewer) needs Phase 1 + SDL2/GAL bridging. Not
achievable in a single autonomous run; needs sustained multi-day
work.
